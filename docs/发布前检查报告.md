**结论: 通过**

### 1.3 路由冲突检查

**结论: 通过**

## 三、权限检查

### 3.1 权限系统架构

项目采用三层权限控制：

1. **全局登录检查** (`app.py` 的 `before_request.require_login`): 所有非豁免路由必须登录
2. **装饰器级别**:
   - `@login_required`: 仅需登录
   - `@admin_required`: 需要管理员角色 (session.role == 'admin')
   - `@permission_required(*perms)`: 细粒度权限检查（已定义但**未在任何路由中使用**）
3. **菜单级别** (base.html): 财务和系统菜单根据权限显示/隐藏

### 3.2 权限定义 (models/role.py)

系统定义了以下权限模块：
- `dashboard`: 仪表盘查看、数据报表
- `product`: 商品查看/新增/编辑/删除/导出
- `warehouse`: 仓库查看/新增/编辑/删除
- `supplier`: 供应商查看/新增/编辑/删除
- `inventory`: 库存查看/入库/出库/调拨/盘点/记录
- `purchase`: 采购单查看/创建/编辑/删除/入库
- `platform`: 平台订单查看、API配置
- `system`: 用户/角色/配置/备份/日志/导入管理
- `finance`: 账户/收支/应收/应付/报表管理

### 3.3 权限校验问题

**[严重] `@permission_required` 装饰器已定义但从未使用**

`utils/decorators.py` 中定义了 `@permission_required` 细粒度权限装饰器，但在所有路由文件中**没有任何路由使用它**。这意味着：

- 所有使用 `@login_required` 的路由，只要登录即可访问，不区分角色权限
- 例如：普通操作员用户可以访问 `/finance/accounts`、`/finance/transactions` 等财务路由（只要登录即可），虽然菜单中不显示，但直接输入 URL 即可访问
- 系统管理路由（用户/角色/备份/日志/配置/导入）使用了 `@admin_required`，仅检查 `session.role == 'admin'`，不检查细粒度权限

**受影响的路由（仅有 @login_required，可能需要细粒度权限）**:

| 蓝图 | 路由 | 应有权限 |
|------|------|----------|
| products | create, edit, delete, toggle_status, batch_toggle_status, clear_inventory, force_delete, batch_delete | `product.create`, `product.edit`, `product.delete` |
| products | export | `product.export` |
| customers | add, edit, delete | `supplier.create`, `supplier.edit`, `supplier.delete`（注：客户模块无独立权限定义） |
| suppliers | create, edit, delete | `supplier.create`, `supplier.edit`, `supplier.delete` |
| suppliers | export | 无对应权限定义 |
| warehouses | create, edit, delete | `warehouse.create`, `warehouse.edit`, `warehouse.delete` |
| warehouses | export | 无对应权限定义 |
| inventory | stock_in, stock_out, transfer, adjust | `inventory.stock_in`, `inventory.stock_out`, `inventory.transfer`, `inventory.adjust` |
| inventory | export | `inventory.records` |
| purchase_orders | create, edit, cancel, receive | `purchase.create`, `purchase.edit`, `purchase.delete`, `purchase.receive` |
| finance | 所有路由 | `finance.*` |
| batches | add, edit, delete | 无对应权限定义 |
| stock_transactions | export, print, delete | `inventory.records` |

**[中等] `@admin_required` 仅检查 role 字段，不检查 role_id 关联的角色权限**

`admin_required` 装饰器只检查 `session.get('role') != 'admin'`，如果用户通过角色系统被分配了管理员角色（但 role 字段不是 'admin'），则会被拒绝访问。

**[低] 客户管理缺少独立权限定义**

`PERMISSION_MODULES` 中没有 `customer` 模块的权限定义，客户管理的所有操作仅需登录即可。

### 3.4 权限检查结论

**结论: 存在需要关注的问题**

- 权限系统架构设计完善（角色模型、权限定义、装饰器都已实现）
- **但细粒度权限装饰器 `@permission_required` 未在任何路由中实际使用**
- 菜单级别的权限控制（base.html）仅控制菜单显示，不阻止直接 URL 访问
- 建议在发布前对关键操作路由添加 `@permission_required` 装饰器
