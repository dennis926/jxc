本文档专门针对宝塔面板环境，提供详细的部署和优化配置。

在宝塔【软件商店】中安装：

| 软件 | 版本要求 | 说明 |
|------|---------|------|
| Nginx | 1.20+ | Web 服务器 |

| Python项目管理器 | 可选 | 已停止维护，不推荐 |

### 1.2 Python 环境

宝塔可能预装 Python，但权限可能有问题：

```bash
# 检查 Python 权限
ls -la /usr/bin/python3*

# 如果权限是 -rw-r--r-- 而非 -rwxr-xr-x，需要修复
chmod +x /usr/bin/python3.12
```

## 三、Supervisor 配置（开机自启）

### 3.1 添加守护进程

宝塔【软件商店】→【Supervisor】→【设置】→【添加守护进程】

| 配置项 | 值 |
|--------|-----|
| 名称 | `inventory` |
| 运行用户 | `www` |
| 运行目录 | `/www/wwwroot/your-domain.com` |
| 启动命令 | 见下方 |

**启动命令**（需要使用绝对路径）：

```bash
/www/wwwroot/your-domain.com/venv/bin/gunicorn --preload -w 2 --threads 2 --worker-class gthread --max-requests 500 --timeout 60 -b 127.0.0.1:5001 wsgi:application
```

> ⚠️ `--preload` 不要省略。它让 `create_app()` 只在主进程执行一次，worker 由 fork 产生，
> APScheduler 的后台线程不随 fork 复制，定时备份只会注册一份。去掉后每个 worker 各注册
> 一份任务，同一秒触发会算出相同的备份中间文件名并互相覆盖、截断，产生残缺的 zip
> 和 `No such file or directory` 失败记录。
> 若确实不能使用，请改为 `-w 1`，或给非主 worker 设置 `RUN_SCHEDULER=0`。

### 3.2 关键配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 进程数量 | 1 | 只需一个主进程 |
| 开机自启 | ✅ | **必须勾选，确保重启后自动运行** |

### 3.3 验证配置

添加后，在 Supervisor 管理页面检查：

- 状态应显示 "运行中"
- 点击"日志"按钮，确认无报错

## 四、Nginx 反向代理

### 4.1 添加反向代理

宝塔【网站】→ 点击站点名 →【反向代理】→【添加反向代理】

| 配置项 | 值 |
|--------|-----|
| 代理名称 | `inventory` |
| 目标URL | `http://127.0.0.1:5001` |
| 发送域名 | `$host` |

### 4.2 手动配置（可选）

如果需要更精细控制，点击【配置文件】，添加以下内容到 server 块：

```nginx
# 静态文件由 Nginx 直接处理
location /static/ {
    alias /www/wwwroot/your-domain.com/static/;
    expires 30d;
    access_log off;
}

# 反向代理到 Gunicorn
location / {
    proxy_pass http://127.0.0.1:5001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    
    # 超时设置
    proxy_connect_timeout 60s;
    proxy_read_timeout 60s;
}

# 禁止访问敏感文件
location ~* \.(db|sqlite|log|key)$ {
    deny all;
}
```

## 五、低配服务器优化（2H2G）

### 5.1 Gunicorn 参数优化

| 参数 | 默认值 | 优化值 | 说明 |
|------|--------|--------|------|
| -w (workers) | 4 | 2 | 减少工作进程 |
| --threads | 4 | 2 | 减少线程数 |
| --max-requests | 1000 | 500 | 定期重启防止内存泄漏 |
| --timeout | 30 | 60 | 增加超时时间 |
| --preload | 无 | 开启 | 定时备份只注册一份，不可省略 |

**优化后的启动命令**：

```bash
/www/wwwroot/your-domain.com/venv/bin/gunicorn \
    --preload \
    -w 2 \
    --threads 2 \
    --worker-class gthread \
    --max-requests 500 \
    --timeout 60 \
    -b 127.0.0.1:5001 \
    wsgi:application
```

### 5.2 Nginx 优化

编辑站点 Nginx 配置：

```nginx
# 开启 gzip 压缩
gzip on;
gzip_types text/plain text/css application/json application/javascript text/xml;
gzip_min_length 1024;

# 连接优化
keepalive_timeout 30;
client_body_buffer_size 128k;
```

### 5.3 系统优化

```bash
# 增加文件描述符限制
echo "* soft nofile 65535" >> /etc/security/limits.conf
echo "* hard nofile 65535" >> /etc/security/limits.conf

# 优化内核参数（可选）
cat >> /etc/sysctl.conf << EOF
net.core.somaxconn = 1024
net.ipv4.tcp_max_syn_backlog = 2048
EOF
sysctl -p
```

## 六、常见问题处理

### 6.1 Python 权限错误

**错误信息**：`/usr/bin/python3: Permission denied`

**解决方案**：

```bash
# 方法一：修复权限
chmod +x /usr/bin/python3.12

# 方法二：使用宝塔 Python
# 宝塔安装的 Python 通常在 /www/server/python_manager/versions/
```

### 6.2 Supervisor 命令找不到

**原因**：宝塔的 Supervisor 不在系统 PATH 中

**解决方案**：

```bash
# 使用完整路径
/www/server/panel/pyenv/bin/supervisorctl status

# 或通过宝塔面板管理
# 软件商店 → Supervisor → 设置
```

### 6.3 端口被占用

**错误信息**：`Address already in use`

**解决方案**：

```bash
# 查找并结束占用进程
lsof -i :5001
kill -9 <PID>

# 或直接释放端口
fuser -k 5001/tcp
```

### 6.4 服务无法访问

**排查步骤**：

```bash
# 1. 检查 Supervisor 状态
/www/server/panel/pyenv/bin/supervisorctl status

# 2. 检查端口监听
netstat -tlnp | grep 5001

# 3. 查看应用日志
tail -f /www/wwwroot/your-domain.com/logs/app.log

# 4. 查看 Nginx 日志
tail -f /www/wwwlogs/your-domain.com.log
```

### 6.5 服务器重启后服务未启动

**检查清单**：

1. Supervisor 配置中"开机自启"是否勾选
2. Supervisor 服务本身是否设置为开机自启

```bash
# 检查 Supervisor 服务状态
systemctl status supervisord

# 确保 Supervisor 开机自启
systemctl enable supervisord
```

## 八、定时任务（可选）

### 8.1 数据库自动备份

宝塔【计划任务】→ 添加任务：

| 类型 | Shell 脚本 |
|------|-----------|
| 执行周期 | 每天 02:00 |
| 脚本内容 | 见下方 |

```bash
#!/bin/bash
BACKUP_DIR="/www/wwwroot/your-domain.com/backups"
DATE=$(date +%Y%m%d_%H%M%S)
DB_FILE="/www/wwwroot/your-domain.com/inventory.db"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
cp $DB_FILE $BACKUP_DIR/inventory_$DATE.db

# 压缩备份
gzip $BACKUP_DIR/inventory_$DATE.db

# 删除 30 天前的备份
find $BACKUP_DIR -name "*.gz" -mtime +30 -delete

echo "Backup completed: inventory_$DATE.db.gz"
```

### 8.2 日志清理

| 类型 | Shell 脚本 |
|------|-----------|
| 执行周期 | 每周日凌晨 03:00 |
| 脚本内容 | 见下方 |

```bash
#!/bin/bash
LOG_DIR="/www/wwwroot/your-domain.com/logs"

# 清空超过 7 天的日志
find $LOG_DIR -name "*.log" -mtime +7 -exec truncate -s 0 {} \;

echo "Logs cleaned"
```

## 九、更新部署


## 十、监控与告警

### 10.1 服务监控脚本

创建 `/www/wwwroot/your-domain.com/scripts/health_check.sh`：

```bash
#!/bin/bash
URL="http://127.0.0.1:5001"
LOG="/www/wwwroot/your-domain.com/logs/health.log"

response=$(curl -s -o /dev/null -w "%{http_code}" $URL)

if [ "$response" != "200" ]; then
    echo "$(date): Service unhealthy, status=$response" >> $LOG
    # 可选：发送告警通知
    # curl -X POST "https://api.example.com/alert" -d "message=Service down"
    
    # 可选：自动重启服务
    # systemctl restart inventory
fi
```

添加到宝塔【计划任务】：
- 类型：Shell 脚本
- 周期：每 5 分钟
