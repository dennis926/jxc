## 首次部署

### 方式一：交互式一键安装（推荐）

```bash
# 1. 克隆项目
cd /www/wwwroot/your-domain.com
git clone https://gitee.com/den7hon/jxc.git .

# 2. 执行一键安装
bash deploy/install.sh
```

脚本会自动：
- 检测系统环境（Python、Git、Nginx、Supervisor）
- 交互式询问是否安装缺失环境
- 创建虚拟环境、安装依赖
- 初始化数据库
- 配置开机自启服务
- 配置 Nginx 反向代理

### 方式二：手动部署

参考 `deploy/install.sh` 中的步骤手动执行。

## 百度网盘备份（可选）

自动备份邮件发送后，系统会尝试将压缩备份上传到百度网盘。上传失败不会影响本机备份或邮件；上传未成功时不会清理本机旧备份。

新服务器需单独准备百度网盘命令行工具及登录状态：

- 安装 `BaiduPCS-Go`，并确保运行 JXC 服务的系统用户可执行。
- 为运行用户完成百度网盘登录；登录状态目录通过 `JXC_BAIDU_HOME` 指定。
- 若不配置，程序默认使用 `/usr/local/bin/BaiduPCS-Go` 和 `/var/lib/site-backup-manager/baidu`；新服务器通常应覆盖默认值。
- 可在 systemd 服务的 `[Service]` 段配置以下环境变量：

```ini
Environment="JXC_BAIDU_CLI=/usr/local/bin/BaiduPCS-Go"
Environment="JXC_BAIDU_HOME=/var/lib/jxc/baidu"
Environment="JXC_BAIDU_REMOTE_DIR=/服务器备份/进销存"
Environment="JXC_BAIDU_KEEP=30"
Environment="JXC_BAIDU_TIMEOUT=600"
Environment="JXC_BACKUP_KEEP_DAYS=3"
```

确保 `JXC_BAIDU_HOME` 对应目录由服务用户拥有且其中登录状态有效。修改 unit 后执行 `systemctl daemon-reload` 并重启服务。未安装/未登录百度网盘时，备份仍保存本机并照常尝试发邮件，但不会清理本机旧备份。

数据库升级会幂等补充 `backup_history.baidu_path` 和 `backup_history.baidu_status` 两个可空字段，不删除既有备份记录。

## 版本升级

### 升级前须知

| 注意事项 | 说明 |
|---------|------|
| 备份数据 | 升级脚本会自动备份数据库和配置文件 |
| 停机时间 | 升级过程约 1-3 分钟，服务会短暂中断 |
| 回滚机制 | 升级失败可一键回滚到上一个版本 |

### 升级方式

#### 方式一：Git 自动升级（推荐）

适用于通过 Git 克隆的项目：

```bash
# 进入项目目录
cd /www/wwwroot/your-domain.com

# 执行升级脚本
bash deploy/update.sh
```

**升级流程**：

```
┌─────────────────────────────────────────────────────────────┐
│                    版本升级流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 检测运行环境                                             │
│     ├── 检测进程管理器（Systemd/Supervisor）                 │
│     └── 检测虚拟环境                                         │
│                                                             │
│  2. 备份数据                                                 │
│     ├── 备份数据库 (inventory.db)                            │
│     ├── 备份密钥文件 (.secret_key)                           │
│     ├── 备份配置文件 (config.py)                             │
│     └── 备份当前代码                                         │
│                                                             │
│  3. 更新代码                                                 │
│     ├── 显示更新日志                                         │
│     ├── 用户确认                                             │
│     └── git pull origin main                                 │
│                                                             │
│  4. 更新依赖                                                 │
│     └── pip install -r requirements.txt                      │
│                                                             │
│  5. 数据库迁移                                               │
│     └── 自动创建新表（不会删除已有数据）                      │
│                                                             │
│  6. 重启服务                                                 │
│     └── systemctl restart inventory                          │
│                                                             │
│  7. 验证升级                                                 │
│     └── curl http://127.0.0.1:5001                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 方式二：手动上传升级

适用于手动上传代码的场景：

```bash
# 1. 上传最新代码到服务器（通过 FTP/SFTP 等）

# 2. 执行手动升级
bash deploy/update.sh --manual
```

#### 方式三：回滚到上一个版本

如果升级后出现问题：

```bash
# 执行回滚
bash deploy/update.sh --rollback
```

**回滚内容**：
- 恢复数据库到升级前状态
- 恢复密钥文件
- 恢复代码到升级前版本
- 重启服务

### 升级脚本参数

| 参数 | 说明 |
|------|------|
| `--manual` | 手动升级模式（代码已上传，只执行后续步骤） |
| `--rollback` | 回滚到上一个版本 |
| `--skip-backup` | 跳过备份（不推荐） |
| `--help` | 显示帮助信息 |

### 升级示例

```bash
# 标准升级
bash deploy/update.sh

# 手动升级（已上传代码）
bash deploy/update.sh --manual

# 跳过备份（快速升级，不推荐）
bash deploy/update.sh --skip-backup

# 回滚
bash deploy/update.sh --rollback
```

## 开机自启配置

### 方式一：Systemd 服务（推荐）

```bash
# 复制服务文件
sudo cp deploy/inventory.service /etc/systemd/system/

# 修改文件路径（重要！）
sudo sed -i 's|/www/wwwroot/your-domain.com|实际路径|g' /etc/systemd/system/inventory.service

# 启用开机自启
sudo systemctl daemon-reload
sudo systemctl enable inventory
sudo systemctl start inventory
```

### 方式二：宝塔 Supervisor

宝塔面板 → 软件商店 → Supervisor → 添加守护进程：

| 配置项 | 值 |
|--------|-----|
| 名称 | `inventory` |
| 运行用户 | `www` |
| 运行目录 | `/www/wwwroot/your-domain.com` |
| 启动命令 | `/www/wwwroot/your-domain.com/venv/bin/gunicorn --preload -w 2 --threads 2 --worker-class gthread --max-requests 500 --timeout 60 -b 127.0.0.1:5001 wsgi:application` |
| 开机自启 | ✅ 勾选 |

> ⚠️ `--preload` 不要省略，否则每个 worker 各注册一份定时备份任务，
> 同一秒触发会产生残缺的备份包。详见 `deploy/inventory.service` 的说明。

### 方式三：独立配置脚本

```bash
# 使用默认端口 5001
bash deploy/setup_service.sh

# 使用自定义端口
bash deploy/setup_service.sh 8000
```

## 迁移到新服务器

本系统为单目录 + 单文件 SQLite，迁移成本极低。假设目标服务器已装好 Python 3.10+ 与 Nginx。

### 1. 源服务器打包

```bash
cd /www/wwwroot/jxc
sudo systemctl stop inventory          # 停服，保证 inventory.db 一致
tar -czf /tmp/jxc_migrate.tar.gz \
    --exclude=venv --exclude=__pycache__ --exclude=.cache \
    --exclude=logs --exclude=backups .
sudo systemctl start inventory         # 立即恢复服务
```

数据库 `inventory.db` 与密钥 `.secret_key` 已包含在包内，无需单独导出。

### 2. 传到目标服务器并部署

```bash
scp /tmp/jxc_migrate.tar.gz user@新服务器IP:/tmp/
# 在目标服务器：
mkdir -p /www/wwwroot/jxc && tar -xzf /tmp/jxc_migrate.tar.gz -C /www/wwwroot/jxc
cd /www/wwwroot/jxc
python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt
sudo install -m 644 deploy/inventory.service /etc/systemd/system/inventory.service
sudo systemctl daemon-reload && sudo systemctl enable --now inventory
# Nginx 反代到 127.0.0.1:5001
```

### 3. 时区无需特殊处理

`app.py` 与 `inventory.service` 内均强制 `TZ=Asia/Shanghai`，只要目标服务器
`/usr/share/zoneinfo/Asia/Shanghai` 存在（绝大多数 Linux 默认存在），部署后时间即自动为北京时间。
若目标为极简容器缺失该文件，可在 systemd 单元的 `[Service]` 段显式加 `Environment="TZ=Asia/Shanghai"`。

### 4. 验证

```bash
curl -s -o /dev/null -w "%{http_code}" https://jxc.hons.fun/   # 期望 302
sudo journalctl -u inventory -n 20
```

## Nginx 配置

### 宝塔面板配置

1. 网站 → 站点设置 → 反向代理
2. 添加反向代理：
   - 目标URL: `http://127.0.0.1:5001`
   - 发送域名: `$host`

### 手动配置

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/inventory
sudo ln -s /etc/nginx/sites-available/inventory /etc/nginx/sites-enabled/
sudo nginx -t && sudo nginx -s reload
```

## 常见问题

### Q1: 升级失败如何回滚？

```bash
bash deploy/update.sh --rollback
```

### Q2: 服务启动失败

```bash
# 查看日志
tail -f /www/wwwroot/your-domain.com/logs/app.log

# 或
sudo journalctl -u inventory -f
```

### Q3: 数据库损坏

```bash
# 从备份恢复
cp /www/wwwroot/your-domain.com/backups/update_xxx/inventory.db \
   /www/wwwroot/your-domain.com/inventory.db
```

### Q4: 服务器重启后服务未启动

```bash
# 检查是否启用了开机自启
sudo systemctl is-enabled inventory

# 如果未启用
sudo systemctl enable inventory
```

## 文件清单

| 文件 | 说明 |
|------|------|
| `deploy/install.sh` | 交互式一键安装脚本 |
| `deploy/update.sh` | 版本升级脚本（含回滚功能） |
| `deploy/setup_service.sh` | 独立的开机自启服务配置脚本 |
| `deploy/inventory.service` | Systemd 服务模板（**线上实际使用**，服务名 `inventory`，含 `TZ=Asia/Shanghai`） |
| `deploy/jxc.service` | 历史遗留的 systemd 模板（服务名 `jxc`，未启用；请勿与 inventory 同时启用，会争抢 5001 端口） |
| `deploy/nginx.conf` | Nginx 配置模板 |
| `deploy/宝塔部署指南.md` | 宝塔面板专用指南 |

> 两个 `.service` 模板监听同一端口（127.0.0.1:5001），**择一启用即可**：线上统一使用
> `inventory.service`（服务名 `inventory`）。切勿同时启用两者，否则会因端口冲突而启动失败。
